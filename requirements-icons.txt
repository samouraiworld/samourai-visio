# Pinned by version AND by hash, so this job resolves the same artefact
# every run — the rule the workflow already applies to every action SHA.
# Only the artefacts the runner can use: the CPython 3.12 manylinux x86_64
# wheel, plus the sdist, so a platform change fails loudly instead of quietly
# resolving something else.
#
# The cp312 musllinux x86_64 wheel is published and deliberately absent: this
# job runs on ubuntu-latest, which is glibc. Listing it would widen what pip
# may accept without widening what the job can run, and the loud failure is
# the point of the curated set.
#
# Regenerate — one command per artefact, into an EMPTY scratch directory:
#
#   d=$(mktemp -d)
#   pip download Pillow==<version> --no-deps --only-binary=:all: \
#       --python-version 3.12 --platform manylinux_2_28_x86_64 -d "$d"
#   pip download Pillow==<version> --no-deps --no-binary=:all: -d "$d"
#   pip hash "$d"/*.whl "$d"/*.tar.gz
#
# The 11.x line also published a manylinux_2_17 wheel and the recipe had a
# third command for it. The 12.x line does not: pip reports no such
# distribution, and its version list for that platform stops at 12.2.0 --
# omitting only the version asked for, which reads like "12.3.0 does not
# exist" and is not. The list is filtered by the platform requested and pip
# does not say so. Check the release's file list on PyPI before concluding an
# artefact is missing.
#
# The sdist command builds what it downloads, so it can fail on a machine
# without Pillow's build dependencies even though the artefact is fine. It did
# on one machine here and not on another, so treat it as environment-dependent
# rather than expected. When it happens the digest is still verifiable from
# the release's own metadata; it is the same value.
#
# Not `-d .`: neither `pillow-*.whl` nor the tarball is in .gitignore, so the
# artefacts land untracked in the tree — and the glob would then hash whatever
# an earlier bump left behind, pinning a digest nobody chose. An empty
# directory per run is what makes the glob mean what it says.
#
# `--python-version` here and `python-version` in the workflow's
# `setup-python` step are one decision in two places. Move them together: the
# hashes name CPython 3.12 wheels, so a job on 3.13 finds nothing it can
# install and `--require-hashes` fails the build rather than falling back.
Pillow==12.3.0 \
    --hash=sha256:78cb2c6865a35ab8ff8b75fd122f6033b92a62c82801110e48ddd6c936a45d91 \
    --hash=sha256:3b8182a766685eaa002637e28b4ec8d6b18819a0c71f579bf0dbaa5830297cce

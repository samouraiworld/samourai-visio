# Greffon catalog entry — Samouraï Visio (DRAFT)

Packaging of our Visio deployment as a [Greffon](https://greffon.io) catalog
entry, so the instance can be deployed (and reinstalled) through Greffon instead
of by hand — and so Visio shows up in Greffon's catalog.

**Status: draft, pending the gates in the last section.** This is staged here as
the source of truth; the files copy verbatim into
[`greffon-catalog`](https://github.com/greffon/greffon-catalog) under
`visio-samourai/1.0/` (name TBD — see below).

```
visio/1.0/
  ├── metadata.json       generated by scripts/build-greffon.py from theme/custom.css
  ├── docker-compose.yml  sign-in closed, single-origin, no recording
  └── smoke_test.spec.ts  (TODO — see gates)
```

## This is NOT the stock `visio` entry

greffon-catalog already ships a `visio/1.0` entry. It is a **self-contained
demo**: bundled Keycloak (`demo` / `demo`), MinIO recording, per-instance
`{{ instance_url }}`. Ours is the **Samouraï product**:

| | stock `visio/1.0` (demo) | this entry (Samouraï) |
|---|---|---|
| Auth | bundled Keycloak, demo login | **sign-in closed**: guests join by link, no account |
| Identity is | throwaway, per-instance | none (the hosted instance uses realm `samourai-app` at `auth.kodera.io`, whose client knows only `visio.samourai.app`) |
| Recording | MinIO + Celery | **none in v1** |
| Images | v1.19.0 | **v1.24.0** |
| Config | `openid email`, JSON lists | **`profile` scope, comma lists, `preferred_username`, PKCE, `OIDC_STORE_ID_TOKEN=false`** |
| Theme | upstream | **Samouraï** (`/custom/style.css`) |
| Intent | "spin up your own Meet" | "the one Samouraï instance" |

They can coexist in the catalog under different names.

## How Greffon maps our stack

- **Proxy + TLS**: Greffon provides them. We keep only an internal `gateway`
  nginx for single-origin routing (`/` → frontend, `/api` `/admin` → backend,
  `/livekit/` → signaling). It sets `X-Forwarded-Proto: https` authoritatively.
- **Secrets**: `DJANGO_SECRET_KEY`, `DB_PASSWORD`, `LIVEKIT_API_SECRET` are
  `greffon-secret` — Greffon mints them. The `DB_PASSWORD` fans out to both
  `backend` and `postgresql`; `LIVEKIT_API_SECRET` is shared between `backend`
  and the rendered `livekit.yaml`, so the two-file mismatch footgun is gone.
- **Sign-in**: closed. The six `OIDC_*` provider and client settings are
  present and empty in the compose file, the gateway answers the sign-in routes
  410, and the package's copy of the theme hides the sign-in button. There is no
  client id or secret to ask for on the install form.
- **Media**: one UDP port as an `l4` `same_port` port; the rendered
  `livekit.yaml` advertises `{{ instance_l4_host }}:{{ instance_l4_port }}`.
- **Mail**: the `smtp` destination type pulls from Greffon's operator SMTP.

Regenerate `metadata.json` after any theme change:

```bash
scripts/build-greffon.py   # re-reads theme/custom.css, re-emits metadata.json
```

## Gates before this ships

1. **Sign-in, if wanted — the blocker.** A Keycloak client allows exact
   redirect URIs only, so each instance would need its own client registered for
   `{{ instance_url }}/api/v1.0/callback/`, or the instance must bind to a
   stable domain known in advance. **Confirm Greffon supports pinning a custom
   domain per instance.** Until then the package ships with sign-in closed.
2. **Display names.** With sign-in closed nobody has an account; if it opens,
   take `OIDC_USERINFO_FULLNAME_FIELDS` from the host template
   (`given_name,family_name`).
3. **Backend without object storage.** Recording is dropped, so no S3 vars are
   set. Verify the backend boots and `migrate` runs without them; if it insists
   on storage config, add a minimal MinIO like the demo.
4. **Restrictive networks.** Single UDP media port, no TURN, no TCP fallback —
   a 443-only client gets no media (same as the demo). Decide whether that's
   acceptable for a public instance or whether TURN needs adding (a second l4
   port + a different topology).
5. **Smoke test.** With sign-in closed there is no login to test.
   The **guest path can**: `ALLOW_UNREGISTERED_ROOMS=true` lets an anonymous
   visitor join an unknown room slug — that's the assertion to automate.
6. **Entry name.** `visio-samourai`, `samourai-visio`, or a variant of the
   existing `visio` — Ghost's call, to avoid colliding with the demo entry.

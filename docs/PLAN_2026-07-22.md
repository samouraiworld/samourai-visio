## Stage 1 — Visio

### 1.1 What Meet actually requires

From `apps/meet/docs/installation/compose.md`. The **production** compose example is 5 services, not the 15 in the dev `compose.yml`:

| Service | Purpose | Notes |
|---|---|---|
| PostgreSQL | Main database | Provided in the example compose |
| Redis | Cache + inter-service | Provided |
| **LiveKit** | WebRTC SFU | The cost driver. Multiplexed on a single UDP port in the example; a port *range* performs better |
| **OIDC provider** | Auth | **Mandatory.** Keycloak example provided |
| SMTP | Invitations | External — Resend is already in use at the coop |

Plus a reverse proxy with TLS (nginx-proxy + Let's Encrypt example provided, or Caddy).

**Explicitly out of scope for v1:** recording, transcription, summarisation, telephony. Each pulls in MinIO, `livekit-egress`, and dedicated Celery workers (`celery-summary-transcribe`, `celery-summary-summarize`), and transcription wants real compute. Ship without them; add later if members ask.

### 1.2 The access model — better than expected

- `ALLOW_UNREGISTERED_ROOMS = True` → **guests join by link with no account**
  *(code default is `True` at `settings.py:665`, but the production env template ships `False` and the env file wins — see [RUNBOOK §4 trap 1](../RUNBOOK.md))*
- OIDC login is required only to **own/administer** a room
- Django session cookie, 12h default

> Anyone can *use* Visio with zero friction.
>
> ⚠️ **Corrected 2026-07-22.** This section previously claimed *"only room creation needs an identity, and that boundary is exactly where 'Samouraï Member' will sit in Stage 5."* That boundary **does not exist**. The flag fires on `Http404` — a slug not in the database — so a working room materialises from any URL with no account at all (`core/api/viewsets.py:257-277`). What an account actually buys is a *persistent, owned, administrable* room. That is still a viable paid gate, but it is not the one Stage 5 was designed around, and it is also why ad-hoc rooms are unattributable for moderation. See [CTO_REVIEW §3.8](CTO_REVIEW_2026-07-22.md).

### 1.3 Network

DNS records needed (3 subdomains on the chosen apex):

| Host | Points to |
|---|---|
| `visio.<domain>` | Meet frontend |
| `id.<domain>` | OIDC provider (Keycloak) |
| `livekit.<domain>` | LiveKit SFU |

Firewall:

```
80/tcp    TLS issuance
443/tcp   HTTPS + TURN/TLS
443/udp   TURN/TLS
7881/tcp  WebRTC ICE over TCP
7882/udp  WebRTC multiplexing over UDP
```

### 1.4 Branding

`FRONTEND_CUSTOM_CSS_URL` → runtime CSS injected via `<link>` in `<head>`. Overrides all design-system tokens (colours, fonts, spacing). **No rebuild, no fork, survives upstream upgrades.**

⚠️ **Corrected 2026-07-22.** The variable is `FRONTEND_CUSTOM_CSS_URL`, not `FRONTEND_CSS_URL`. Tokens are **Panda CSS** (`--colors-*`), not Cunningham. And the raw Kodera palette fails WCAG AA — `#FD6262` on white is 2.96:1 — so the deployed theme darkens the fill and text steps and keeps coral as a decorative accent. The browser-tab name needs a rebuilt image, which we decline. See [RUNBOOK §7](../RUNBOOK.md).

### 1.5 Operational policy — decide before launch, not after

A free public WebRTC service with open signup is a bandwidth and moderation liability. Minimum policy:

- **Retention**: monthly reset of rooms/accounts (this is what lasuite.coop does — it's a proven, defensible norm, and it caps storage growth)
- **Caps**: max participants per room, max room duration
- **CGU + abuse contact** published before any promotion
- **Pinned image tags** — the compose example defaults to `latest`; pin them or an upstream push will restart your production stack unannounced

### 1.6 Cost

LiveKit egress scales with **participant-minutes**, not signups. Zentai's own ROADMAP estimated LiveKit at 30 €/mo (1 node) → 150 €/mo (3 nodes).

Estimate for the full v1 stack on one Scaleway instance: **~60–150 €/mo**, dominated by bandwidth. ⚠️ **Unvalidated** — benchmark at 10 / 50 / 200 concurrent participants before promising a free service publicly.

### 1.7 Deploy steps

1. Provision the instance; open the 5 ports
2. Point the 3 DNS records
3. `curl` the six upstream config files (compose.yaml, .env, env.d/common, env.d/postgresql, livekit-server.yaml, default.conf.template)
4. Generate secrets: `DB_PASSWORD`, `LIVEKIT_API_SECRET`, `DJANGO_SECRET_KEY`
5. Stand up the OIDC provider; create the `meet` client → `OIDC_RP_CLIENT_ID` / `OIDC_RP_CLIENT_SECRET`
6. Wire Resend SMTP (`DJANGO_EMAIL_*`, `DJANGO_EMAIL_BRAND_NAME`, `DJANGO_EMAIL_LOGO_IMG`)
7. Reverse proxy + Let's Encrypt
8. `docker compose up -d` → `manage.py migrate` → `createsuperuser`
9. Publish `custom.css`, set `FRONTEND_CSS_URL`
10. Smoke test: 3-way call, screenshare, guest-join-by-link, mobile browser

### Positioning

Not a monitoring dashboard — `ecosystem.code.gouv.fr` (a state-run Ecosyste.ms instance: 33,969 repos, 8.4M dependencies) owns the package layer.

**Own the people layer.** Who contributes, who's rising, which teams collaborate, what shipped this week. Gnolove's original DNA is a gamified contributor scoreboard tagged `opensourceforgood` — that is the right instinct, already in the code.

## Stage 4 — Gamification / incentives

⚠️ **Design not settled.** Gnolove already ships scoring (commit ×10, PR ×2, review ×2, issue ×0.5), leaderboards, and teams. "Incentivised" implies something beyond points, and the mechanism is an open decision:

- **Recognition only** — badges, streaks, weekly spotlight, shareable profile cards. Zero liability, zero cost.
- **On-chain attestation** — Memba already runs quests/XP with on-chain attestation and a verify-worker. Reusable, but couples a French public-sector audience to a blockchain, which may repel more than it attracts.
- **Real rewards** — bounties, swag, membership credits. Highest pull, but needs funding and creates obligations.

Note a genuine hazard: scoring **other people's** contributors without asking can land badly. Gnolove scored a community Samouraï was already inside. La Suite is not that. Recognition framing and an opt-out are cheap insurance.

## Stage 5 — Samouraï Member + products

Zentai's STRATEGY.md already specifies a 5 €/mo Premium tier. Make it **one adhésion** across the coop's surface — Visio, Zentai, whatever follows — rather than several subscriptions. Coop-native: members get access *and* a voice.

The Stage 1 auth boundary (login required to create a room, guests join free) is already the natural gate. Nothing to re-architect.

**Break-even at 5 €/mo: ~20–40 members**, given Stage 1 costs.

Market position — deliberately not lasuite.coop's:

| | lasuite.coop | Samouraï |
|---|---|---|
| Customer | Organisations 10+ | Individuals, freelances, collectifs 1–9 |
| Motion | Sales-led, 500–1 500 € deployment | Self-serve, zero setup |
| Channel | B2B / ESS networks | YouTube 13k, dev community |
| Price | 150–500 €/mo | 5 €/mo |

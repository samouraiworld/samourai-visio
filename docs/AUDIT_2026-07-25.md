Two hardenings rode along: `umask 077` (cron's default left every dump `0644` —
world-readable emails and room metadata) and the remote prune now asserts its
**invariant** (oldest surviving object) rather than trusting `rclone delete`'s
exit code, because the 30-day figure is published in the privacy policy.

**New CI job `Backup end-to-end`.** `backup.sh` guards the only rollback this
deployment has and **no CI step had ever executed it** — shellcheck parses, it
does not run. The job now stands up a real Postgres, builds a >10 MB fixture
(deliberately past the pipe buffer), asserts the OK path, the marker, the remote
object and the file mode, then makes the remote unwritable and asserts it fails
loudly and writes **no** marker.

**And a correction to our own documentation.** The `SENTRY_DSN` "trap" note was
**inverted** in both `deploy/env.d/common.example` and roadmap 1.6. Tested
against upstream's own pin (`django-configurations==2.5.1`):

```
DJANGO_SENTRY_DSN=x                    -> 'x'    works
SENTRY_DSN=x                           -> None   ignored silently
SENTRY_DSN=x with environ_prefix=None  -> 'x'    control, proves the mechanism
```

`environ_name` does **not** suppress the `DJANGO_` prefix; only
`environ_prefix=None` does, which upstream passes elsewhere but not for Sentry.
So the docstring was right and the bare name our template recommended is the
dead one. Left unfixed, 1.6 would have wired a DSN that is accepted, never used,
and never warns. `preflight.sh` now fails on the bare form.

## 1. Production defects found on the live instance

### 1.1 Django-rendered pages return 500 and every `/static/` asset 404s — **high**

Verified live: `https://visio.samourai.app/admin/login/` → **HTTP 500**;
`/static/admin/css/base.css` → 404. Cause:
`deploy/compose.override.yaml` mounts `./data/backend:/data`, which **shadows the
image's baked `STATIC_ROOT`** at `/data/static`. The mount was added for a
future upload feature; it silently broke everything Django renders itself.

*Fix:* mount only `./data/backend/media:/data/media`, correct the comment, and
assert `/static/admin/css/base.css` returns `text/css` in `preflight.sh public`.

### 1.2 Django admin is publicly reachable, and the RUNBOOK tells the operator to create its password — **high**

`https://visio.samourai.app/admin/` answers publicly (302 to the login page) via
`location /admin` in our own gateway file. Django's admin has no brute-force
protection and no MFA, and upstream ships neither `django-axes` nor
`django-ratelimit`. Every real user authenticates through Clerk — the admin
password is a second, weaker path to the entire database, and a successful login
allows inserting a `ResourceAccess` row that grants `roomAdmin` on any room.

*Today's accident:* finding 1.1 means the login page 500s, so it is not
exploitable right now. Fixing 1.1 without fixing this would open it.

*Fix:* `location /admin { return 404; }` (or allow-list the operator's address);
reach it via `ssh -L` + `docker compose exec`. Update RUNBOOK §…, and assert the
404 in `preflight.sh public`. **Needs your decision** — it changes ops workflow.

### 1.3 Anonymous LiveKit tokens are unthrottled — the instance is a free SFU/TURN relay — **high**

One unauthenticated GET returns a signed 6-hour token granting
`roomJoin` + publish over camera/mic/screen-share for an arbitrary room name
(verified live). Nothing rate-limits it: upstream's `retrieve` declares no
throttle classes and `settings.py` defines `DEFAULT_THROTTLE_RATES` but no
`DEFAULT_THROTTLE_CLASSES`, so DRF throttles nothing. With `auto_create: true`,
500 scripted GETs mean up to 500 rooms × 30 publishers, all billed as Scaleway
egress; a token is also a free TURN allocation, making the host a general-purpose
UDP relay. No attribution survives: rooms have no owner and IPs age out in 7 days.

*Fix:* `limit_req` on `location /api/v1.0/rooms/` in the SAMOURAI block —
**with the trap handled**: the gateway sits behind nginx-proxy, so
`$remote_addr` is always the proxy's container IP and a naive
`limit_req_zone $binary_remote_addr` would throttle the whole internet as one
client. Needs `set_real_ip_from` + `real_ip_header X-Forwarded-For` first. Add
LiveKit's `limit:` block (`num_tracks`, `bytes_per_sec`) too. **Design decision —
worth doing before promotion.**

### 1.4 No framing/CSP headers, and two HSTS headers where the 60-second one wins — **medium**

Only `strict-transport-security` is present on any response — no CSP,
`X-Content-Type-Options`, or `Referrer-Policy`. Worse, two HSTS headers are
emitted (`max-age=60; includeSubDomains; preload` from Django and
`max-age=31536000` from nginx-proxy — both verified live); per RFC 6797 the UA
processes the first, so **HSTS effectively expires 60 seconds after the last API
call**, and a `preload` directive is being advertised on a 60-second policy.

*Fix:* `proxy_hide_header Strict-Transport-Security` in the two proxy blocks,
emit exactly one policy at server level, and add `frame-ancestors 'self'`,
`nosniff`, `Referrer-Policy` inside a SAMOURAI marker so the contract diff keeps
tracking them.

## 2. Legal — the pages are strong; five gaps remain

1. **Missing LCEN fields beyond the pending phone** — share capital, the RCS
   registration mention, and the host's telephone number. Bundle with 1.2.
2. **The Clerk transfer safeguard is misstated** — the policy names the SCCs,
   while Clerk's own DPA makes the **EU-US Data Privacy Framework** primary with
   SCCs as fallback; art. 13(1)(f) also requires saying how to obtain a copy.
3. **The CGU are browse-wrap only** — sign-up captures no acceptance
   (Clerk `legal_consent_enabled=false`), which weakens the suspension clause the
   CGU rely on. Cross-app decision: the account is shared with Memba/Zentai.
4. **Invitee e-mail addresses** are in the processing table but absent from the
   retention table, and the invitation carries no privacy notice (art. 14(3)(b)).
5. **Consumer-law polish** — no *médiation de la consommation* reference; the
   landing says recording is "impossible" while the CGU correctly say local
   recording is always possible (the CGU wording is the honest one).

## 3. Operations

- **Only the database leaves the box — high.** Secrets, `livekit-server.yaml`,
  the gateway template, compose files and the nginx-proxy ACME/cert volumes have
  no off-box copy. Host loss means rebuilding config from the repo plus secrets
  that exist nowhere else. *Fix:* ship an age-encrypted config bundle to the same
  bucket, recovery key held off the box.
- **Certificate renewal failure is invisible until the outage — medium.** No
  expiry-margin check anywhere, and Let's Encrypt no longer sends expiry mail, so
  RUNBOOK §5's `DEFAULT_EMAIL` reasoning is stale. *Fix:* `openssl x509 -checkend`
  at 21 days in `preflight.sh public`.
- **Disk-full is unmonitored and actively fed — medium.** Pre-upgrade dumps are
  never pruned and §10 never prunes superseded images, against a 1 GB journal cap
  plus dumps.
- **An unedited cron template passed both checks — low.** Fixed in PR #19 (the
  check counted comment lines).
